# AmneziaWG — VPN поверх UDP

Ставится, когда у оператора на той стороне **режут TLS к адресу
сервера**. Признак: не проходит ни один вариант VLESS — ни REALITY
поверх TCP, ни поверх xhttp, ни Shadowsocks, у которого рукопожатия
TLS нет вовсе, — а TCP при этом устанавливается, и в журнале Xray на
каждую попытку `failed to read client hello`.

AmneziaWG — WireGuard с забитой сигнатурой: перед рукопожатием шлётся
мусор, заголовки пакетов подменены, и фильтр не опознаёт протокол по
первому пакету. Работает поверх **UDP** — то есть мимо всего, что
происходит с TLS.

Бота и Xray не трогает: у тех TCP-порты, здесь UDP 51820.

## Установка

```bash
sudo sh deploy/awg.sh install
```

Минут пять. Ставит Go и инструменты сборки, собирает `amneziawg-go` и
`amneziawg-tools` из исходников, генерирует ключи и параметры
обфускации, поднимает интерфейс, включает пересылку и подмену адреса,
прописывает службу и печатает конфиг первого клиента с QR-кодом.

Собираем из исходников намеренно: готовых пакетов для Debian нет, а
ядерный модуль требует заголовков ядра и DKMS — на VPS это лишний риск
ради скорости, которой на канале в гигабит всё равно не заметить.
Userspace-реализация работает на любом ядре.

## Клиенты

```bash
sudo sh deploy/awg.sh add masha     # конфиг и QR
sudo sh deploy/awg.sh config masha  # показать снова
sudo sh deploy/awg.sh list          # кто заведён
sudo sh deploy/awg.sh remove masha  # отобрать доступ
sudo sh deploy/awg.sh status        # что со службой
```

У каждого человека свой клиент: с общим ключом нельзя отобрать доступ у
одного, не сломав всем.

Конфиг удобнее отдавать **файлом** `имя.conf`, а не QR: QR в терминале
часто сканируется с ошибкой, а файл импортируется точно.

## Приложения

**Только те, что умеют AmneziaWG.** Обычные клиенты WireGuard не
подойдут — обфускацию они не понимают и молча не подключатся.

| Где | Чем |
|---|---|
| iPhone, Android | **Amnezia VPN** (amnezia.org) или **AmneziaWG** |
| macOS, Windows | **Amnezia VPN** |

Happ и подобные здесь не годятся: это другой протокол.

## Что внутри

Параметры обфускации обязаны совпадать у сервера и каждого клиента **до
единого числа**: это часть протокола, а не настройка. Поэтому они лежат
в одном месте (`/etc/amnezia/amneziawg/peers.json`) и подставляются в
оба конфига оттуда.

Значения взяты из самого Amnezia — `protocolConstants.h` и
`awgInstaller.cpp` в [amnezia-client](https://github.com/amnezia-vpn/amnezia-client).
Это то, что раздаёт их собственное приложение, и оно работает у живых
людей; выдумывать своё тут незачем.

Протокол версии **3.1**, и он устроен не так, как первый AmneziaWG:

- `H1`–`H4` — **штатные** 1, 2, 3, 4, а не случайные. Прятать их
  рандомизацией больше не нужно: `HeaderProtectionKey` шифрует заголовки
  целиком, и это сильнее. Случайные заголовки, наоборот, сами примета.
- `I1` — поддельный DNS-запрос к `icloud.com`: первый пакет клиента
  выглядит как обращение к имени, а не как начало туннеля. Отправляет
  его клиент, поэтому у сервера этого параметра нет.
- `RandomTrailers`, `DisableCookies`, `ContentPaddingAddition` и
  разбросы времён (`RekeyAfterTime`, `KeepaliveTimeout` и прочие)
  убирают постоянство в размерах и ритме пакетов.

Порт по умолчанию — **55424**, а не 51820: штатный порт WireGuard режут
по одному номеру, не заглядывая внутрь. Тоже как у Amnezia.

Проверяется до записи конфига: `Jmin` меньше `Jmax`, размеры вставок в
пределах, `S1 + 56` не равно `S2` (иначе замусоренный пакет совпадёт по
длине с настоящим), `H1`–`H4` различны, `HeaderProtectionKey` не пуст.

Ещё две вещи, без которых туннель поднимается, а интернета нет:
пересылка пакетов (`ip_forward`) и подмена адреса (`MASQUERADE`) —
обе в `PostUp`, и обе снимаются в `PostDown`. `PersistentKeepalive`
у клиента нужен для мобильных сетей: они рвут неактивные соединения
через минуту-две.

## Если не подключается

```bash
sudo sh deploy/awg.sh status
sudo journalctl -u amneziawg -n 30 --no-pager
```

**Порт не слушается** — служба не поднялась, смотрите журнал.

**Слушается, а клиент не подключается** — скорее всего, у оператора на
той стороне режут UDP. Это единственное, чего обфускация не лечит: она
прячет протокол, но не создаёт канал там, где его нет. Тогда остаётся
маршрут через CDN, см. [VLESS.md](VLESS.md).

**Подключился, но интернета нет** — пересылка или NAT. Проверьте:

```bash
sysctl net.ipv4.ip_forward          # должно быть 1
iptables -t nat -S POSTROUTING | grep 10.8.0
```

## Снести

```bash
sudo sh deploy/awg.sh uninstall
```

Бота, Xray и VLESS не трогает.
