# VPN на том же сервере: VLESS + Reality

Тот же Netcup, где живёт бот. Xray встаёт на 443/tcp, бот не слушает
ни одного порта — он только сам ходит наружу, — поэтому рассылка в
11:00 и кнопки продолжают работать как работали.

## Почему Reality, а не WireGuard

WireGuard опознаётся по сигнатуре первого пакета: российские ТСПУ
режут его на магистрали, независимо от того, где стоит сервер. Reality
такой сигнатуры не даёт. Клиент начинает настоящее TLS-рукопожатие с
реальным чужим сайтом (в конфиге он называется маскировочным доменом),
и только внутри уже установленного соединения открывается туннель.

Снаружи это неотличимо от похода на этот сайт. Активная проверка тоже
ничего не даёт: если постучаться на 443 без ключа, Xray молча проксирует
запрос на настоящий сайт, и проверяющий видит его, а не VPN.

## Установка

Одна команда на сервере:

```bash
cd ~/inspobot && git pull && sudo sh deploy/vless.sh install
```

Скрипт сам: поставит пакеты, определит внешний адрес, подберёт рабочий
маскировочный домен, установит Xray, сгенерирует ключи, соберёт конфиг,
запустит службу и напечатает ссылку с QR-кодом для первого клиента.

Минут пять, вопросов не задаёт.

Первого клиента зовут `phone`. Другое имя — аргументом:

```bash
sudo sh deploy/vless.sh install vlad-iphone
```

## Клиенты

```bash
sudo sh deploy/vless.sh add masha       # ссылка и QR для нового человека
sudo sh deploy/vless.sh link masha      # показать ссылку ещё раз
sudo sh deploy/vless.sh list            # все, кто есть
sudo sh deploy/vless.sh remove masha    # отобрать доступ
sudo sh deploy/vless.sh status          # жив ли сервер
```

У каждого человека **свой** клиент. Не потому что жалко, а потому что
иначе отобрать доступ у одного нельзя, не сломав всем остальным: ключ
общий. С отдельными клиентами `remove` выключает ровно одного.

## Что ставить людям

| Где | Приложение |
|---|---|
| iPhone, iPad | **v2RayTun** или **Streisand** (обе есть в российском App Store) |
| Android | **v2rayNG** или **Hiddify** |
| macOS | **Hiddify** или **V2Box** |
| Windows | **Hiddify** или **v2rayN** |

Ссылка `vless://…` вставляется из буфера — в любом из них есть кнопка
«импорт из буфера обмена». QR сканируется камерой внутри приложения.
Если QR в терминале не читается (тёмная тема, мелкий шрифт), просто
отправьте ссылку текстом: клиенты понимают её целиком.

## Чинить, если не подключается

```bash
sudo sh deploy/vless.sh status
sudo journalctl -u xray -n 50 --no-pager
```

**Служба активна, порт слушается, а клиент не цепляется** — почти
всегда время на сервере разъехалось с реальным: TLS этого не прощает.
`timedatectl` покажет, `apt install -y systemd-timesyncd` починит.

**Работало и перестало у всех сразу** — возможно, маскировочный домен
заблокировали или он перестал отвечать. Поменять:

```bash
sudo sed -i 's/www.microsoft.com/dl.google.com/g' /usr/local/etc/xray/reality.json
sudo python3 deploy/vless_admin.py render && sudo systemctl restart xray
```

Ссылки клиентов после этого **перестают работать** — в них зашит домен.
Раздайте новые: `sudo sh deploy/vless.sh list`.

**Работает у одного, не работает у другого** — это не сервер. Сначала
проверьте, что у второго в приложении включён именно `xtls-rprx-vision`
и импорт прошёл целиком (ссылку часто обрезают при копировании).

## Что внутри

Конфиг собирается скриптом `deploy/vless_admin.py` из файла
`/usr/local/etc/xray/reality.json` — там ключи, домен и список клиентов.
Сам `config.json` каждый раз генерируется заново: править живой конфиг
по месту значит каждый раз рисковать уронить сервер опечаткой в JSON.

Три решения, принятых за вас:

- **Журнал посещений не ведётся** (`"access": "none"`). На диске не
  копится, кто куда ходил. И приватность, и место: такой журнал растёт
  быстрее всего остального на сервере.
- **Локальная сеть сервера закрыта.** Иначе клиент по туннелю достаёт
  `127.0.0.1` этой машины, а там бот, его база и SSH.
- **Торренты заблокированы.** Жалоба хостеру прилетает на адрес, общий
  с ботом: заблокируют машину — встанет и рассылка.

## Что стоит знать заранее

**Адрес общий у вас и у бота.** Для личного использования нормально, но
это адрес дата-центра: Google иногда показывает капчу, часть стримингов
такие адреса режет.

**Если это станет сервисом — заведите отдельный сервер.** Не из-за
нагрузки (её нет), а из-за абуз: одна жалоба в Netcup блокирует машину
целиком, вместе с ботом. Пока это вы и несколько друзей — общая машина
в порядке.

**Netcup разрешает личный VPN**, но не разрешает публичный сервис и
торренты. Второе скрипт закрывает сам, первое — на вашей совести.

**Правовая сторона.** В России с марта 2024 запрещена реклама и
популяризация средств обхода блокировок — штрафы по КоАП. Сам по себе
VPN для личного использования не запрещён, но публичная раздача доступа
и тем более продажа — зона, где риск несёте вы, а не пользователи. Если
планируете что-то за деньги, это стоит обсудить с юристом, а не со мной.
