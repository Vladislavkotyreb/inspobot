# Доступ к Mobbin MCP

## Почему не просто ключ

У Mobbin два разных интерфейса. **REST API** с ключом из настроек доступен
только на тарифах Team и Enterprise. **MCP-сервер** (`https://api.mobbin.com/mcp`)
работает на Pro, но ключа не выдаёт: он авторизуется по OAuth 2.1 — так же,
как когда MCP подключают в Claude или Cursor. Поэтому вход проходится один раз
руками, а дальше бот сам обновляет токен по refresh-токену.

## Один раз: вход с браузером

На своей машине (не на сервере — там нет браузера):

```bash
git clone https://github.com/Vladislavkotyreb/inspobot
cd inspobot
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m inspobot.auth_cli
```

Скрипт сам находит адреса OAuth по метаданным сервера, регистрирует клиента,
поднимает временный `http://127.0.0.1:<порт>/callback` и открывает браузер.
После входа в Mobbin в `var/mobbin_token.json` появятся access- и refresh-токены.

Скопируйте файл на сервер:

```bash
scp var/mobbin_token.json USER@СЕРВЕР:/opt/inspobot/var/mobbin_token.json
ssh USER@СЕРВЕР chmod 600 /opt/inspobot/var/mobbin_token.json
```

## Дальше

Перед каждым запросом `get_access_token()` смотрит на срок жизни access-токена
и за две минуты до истечения меняет его на новый по refresh-токену; обновлённый
файл перезаписывается на месте. Ничего запускать вручную не нужно.

## Если refresh-токена не дали

Некоторые серверы не выдают refresh-токен. Тогда `auth_cli` честно об этом
скажет, и раз в срок жизни токена вход придётся повторять. Вариант без файла —
положить готовый токен в окружение:

```
MOBBIN_ACCESS_TOKEN=...
```

Это значение всегда важнее файла: удобно для отладки и для случая, когда токен
вы получаете каким-то своим способом.

## Если сервер не поддерживает динамическую регистрацию

`auth_cli` скажет об этом отдельной ошибкой. Тогда заведите OAuth-приложение
в Mobbin руками и добавьте в окружение:

```
MOBBIN_CLIENT_ID=...
MOBBIN_CLIENT_SECRET=...   # если выдали
```

Redirect URI при ручной регистрации нужен вида `http://127.0.0.1:<порт>/callback`;
порт `auth_cli` выбирает случайно, поэтому для ручного сценария удобнее
зарегистрировать несколько фиксированных портов и запускать вход, пока один
из них не совпадёт, либо сразу использовать `MOBBIN_ACCESS_TOKEN`.

## Проверка

```bash
.venv/bin/python -m inspobot.daily --dry-run --verbose
```

Ничего не отправит в Telegram, но сходит в Claude и Mobbin и напечатает
готовую подборку в консоль. Это самый быстрый способ убедиться, что токен жив.
