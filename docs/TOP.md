# Топ-10 за неделю и за месяц

Лучшее из того, что уже присылалось. **Бесплатно**: ни Claude, ни Mobbin
здесь не вызываются, баланс не расходуется.

## Откуда берётся «лучшее»

Оценку каждой находке ставит модель в момент отбора — внутри того же
утреннего запроса, полем `score` от 1 до 10. Это плюс несколько токенов, а не
отдельный вызов. Формулировка в промпте: не «нравится ли», а «стоит ли к этому
вернуться через месяц». Оценки лежат в базе вместе с номерами отправленных
сообщений.

Топ — это выборка из базы за окно (7 или 30 дней), отсортированная по оценке;
одно приложение попадает в топ один раз, даже если все его экраны на девятку.

Картинки не перекачиваются: Telegram **копирует** те самые сообщения
(`copyMessage`), которыми находка уходила в этот чат. Файл тот же, качество
то же. Подпись подменяется на новую — с местом, оценкой и датой. Если в этот
чат находка не уходила (новый подписчик), придёт текстовая карточка с кнопкой.

Ограничение честное: это оценка модели, а не читателей. Реакции и клики бот
не собирает — для этого нужен процесс, который их слушает, а его нет.

## Три способа вызвать

**1. Руками в GitHub.** Actions → «Утренний дайджест» → Run workflow → в поле
*Что делать* выбрать `top-week` или `top-month`. Уйдёт всем получателям.
Ничего настраивать не надо.

**2. Из терминала**, если база под рукой:

```bash
.venv/bin/python -m inspobot.top --week
.venv/bin/python -m inspobot.top --month --chat 458337792
```

**3. Кнопками под шапкой дайджеста.** Вот здесь нужна одна оговорка.

## Кнопки

Нажатие на кнопку — входящее событие, и его должен кто-то принять. На сервере,
который и так работает круглосуточно, для этого хватает маленькой службы:
`inspobot.listener` держит длинный опрос Telegram и на нажатие запускает тот же
`inspobot.top`.

Ставится вместе с расписанием:

```bash
sh deploy/install-server.sh --cron
```

Проверить и посмотреть логи:

```bash
systemctl status inspobot-listener
journalctl -u inspobot-listener -f
```

Кнопки — **постоянная клавиатура** в чате: две подписи внизу экрана, всегда
под рукой. Это не те кнопки, что живут под конкретным сообщением: такие
уезжают вверх вместе с ним, и через день до них уже не долистать.

Появляется клавиатура сама с первой подборкой. Показать её сразу — написать
боту `/start` или `/buttons`.

Включается переменной в `.env`:

```
INSPOBOT_TOP_BUTTONS=1
```

По умолчанию их нет: без службы они висели бы мёртвыми.

Команды `/week` и `/month` делают то же самое — на случай, если клавиатура
скрыта. Второе нажатие, пока топ ещё собирается, отбрасывается: десять
сообщений в две копии забили бы чат.

Если дайджест живёт не на сервере, а в GitHub Actions, принять нажатие
некому — там нет постоянного процесса. Для такого случая в
[`deploy/cloudflare-worker.js`](../deploy/cloudflare-worker.js) лежит
ретранслятор на бесплатном тарифе Cloudflare: он принимает нажатие и дёргает
Actions через `repository_dispatch`.

## Что стоит знать

**После установки вебхука перестаёт работать `getUpdates`** — Telegram не даёт
совмещать. На дайджест это не влияет, а вот `inspobot.doctor` больше не сможет
подсказать `chat_id` новому подписчику: попросите его написать боту и посмотрите
id через [@userinfobot](https://t.me/userinfobot). Снять вебхук, если
понадобится: `curl "https://api.telegram.org/bot<ТОКЕН>/deleteWebhook"`.

**База живёт в артефактах Actions** с хранением 90 дней — этого хватает и
на месячный топ, и с запасом. Подробнее в
[GITHUB_ACTIONS.md](GITHUB_ACTIONS.md).

**Несколько нажатий подряд** запустят несколько сборок; они выстроятся в
очередь и придут по одной. Это не ломается, просто не надо кликать десять
раз.
