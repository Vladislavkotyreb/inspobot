# Как это устроено

## Путь одного дайджеста

```
cron / launchd / systemd-таймер
        │
        ▼
  daily.run_once ──── state.Store: сегодня уже слали? ──► выход
        │
        ├─ profile.load ─────────► расписание недели
        ├─ profile.plan_for_day ─► день недели и по теме на блок ──► None: выходной
        ├─ chats.load ───────────► кому отправлять
        ├─ mobbin_auth.get_access_token ─► токен (обновляется сам)
        │
        ▼
  curator.collect ── один запрос к Messages API
        │  beta mcp-client-2025-11-20
        │  mcp_servers = [Mobbin] + tools = [mcp_toolset]
        │  output_config.format = json_schema
        ▼
   Claude по очереди вызывает нужный инструмент Mobbin для каждого блока,
   смотрит картинки, отбирает и возвращает JSON с полем slot у каждой находки
        │
        ▼
  prompt.parse_digest ─── раскладка по блокам, отсев выдуманного и повторов
        │
        ▼
  render.* ──► telegram.Telegram ──► все чаты из списка
        │
        ▼
  state.Store.mark_seen: эти экраны больше не предлагать
```

Между запусками не живёт ни один процесс. Клиентского цикла `tool_use` тоже
нет: соединение с MCP-сервером Mobbin держит сторона Anthropic, поэтому один
вызов Messages API покрывает и поиск, и просмотр картинок, и отбор по всем
блокам сразу. Вручную обрабатывается только `stop_reason == "pause_turn"` —
запрос продолжается тем же контекстом.

## Модули

| Файл | Ответственность | Зависит от сети |
|---|---|---|
| `catalog.py` | что вообще бывает: виды, платформы, аудитории, темы | нет |
| `profile.py` | расписание недели, ротация тем, чтение и запись | нет |
| `chats.py` | список получателей рассылки | нет |
| `models.py` | `Pick`, `Section`, `Digest` | нет |
| `prompt.py` | системный промпт, JSON-схема, сборка запроса, разбор ответа | нет |
| `render.py` | HTML для Telegram, лимиты длины, экранирование | нет |
| `state.py` | SQLite: что показывали, когда запускались | нет |
| `config.py` | окружение и `.env` | нет |
| `logs.py` | уровни логирования | нет |
| `client.py` | сборка клиента Anthropic, заголовок workspace | нет |
| `curator.py` | вызов Messages API с MCP-коннектором | да |
| `mobbin_auth.py` | OAuth к Mobbin, обновление токена | да |
| `telegram.py` | Bot API | да |
| `daily.py` | собрать и отправить одну подборку | да |
| `doctor.py` | самопроверка доступов, подсказка `chat_id` | да |
| `setup_cli.py` | пошаговая настройка профиля | нет |

Первые девять проверяются тестами целиком, без ключей и без сети. Отсюда и
разделение: `prompt.py` отдельно от `curator.py` именно затем, чтобы разбор
ответа модели проверялся, не платя за запрос.

## Оси выбора соответствуют возможностям Mobbin

Каталог собран не из фантазии, а из схем MCP-инструментов:

| Ось | Чем обеспечена |
|---|---|
| Вид (экран / флоу / секция) | три инструмента: `search_screens`, `search_flows`, `search_sections` |
| Платформа | параметр `platform` (`ios`/`web`); у `search_sections` его нет — для секций шаг пропускается, а `platform` в ответе всегда `web` |
| Тема | текст запроса |
| **B2B / B2C** | **фильтра нет.** Два набора тем со своими формулировками |

Последнюю строку `setup_cli` проговаривает прямо на шаге выбора аудитории:
обещать фильтрацию, которой нет, — худший вид интерфейсной лжи.

## Почему так

**Дедупликация через `exclude_screen_ids`.** Mobbin — не лента новинок, это
поиск. «Новое» здесь означает «новое для вас», поэтому id показанных экранов
уходят в SQLite, а оттуда — в параметр поиска. Память скользящая: Mobbin
принимает не больше 100 значений, так что через несколько месяцев экран может
вернуться. Флоу и секции в память не попадают: у них нет такого параметра,
и хранить их было бы самообманом.

**Ротация считается по номеру недели, а не по дню.** Понедельник приходит раз
в семь суток, поэтому отсчёт по дням сдвигал бы тему на семь позиций за раз —
и застревал бы намертво, когда длина списка кратна семи. Деление порядкового
номера дня на семь даёт ровно один шаг в неделю при любой длине списка. Это
проверяется тестом на списке ровно из семи тем.

**Одна сборка на всех.** Подборка собирается один раз и отправляется в каждый
чат из списка: модель вызывается однажды, поэтому счёт за API не зависит от
числа подписчиков. Чат, который заблокировал бота, пропускается с записью в
лог — рассылка не должна падать из-за одного отписавшегося. Запуск считается
неуспешным, только если не принял никто.

**Пустой день — это решение, а не пробел.** Суббота в расписании по умолчанию
пустая: письмо каждый день без исключений быстро становится фоном.

**Профиль на диске, а не в переменных окружения.** Состав дайджеста — это
структура (список блоков со своими темами), а не пара скаляров. В `.env` она
превратилась бы в нечитаемую строку.

**Один запрос на весь дайджест.** Отдельный вызов на блок был бы дороже и не
дал бы модели видеть подборку целиком — а `summary` про то, что её объединяет,
требует именно этого.

**Флоу — всеми шагами.** `search_flows` возвращает превью каждого экрана
сценария, и модель складывает их в поле `screens`. Отправляются они галереей
(`sendMediaGroup`), а не по одной: десять сообщений подряд на один сценарий
превратили бы дайджест в спам. В галерею влезает десять картинок, длинные
сценарии разбиваются, подпись идёт только к первой части.

**Файлы, а не фотографии.** Telegram сжимает всё, отправленное как фото, и
мелкий текст на скриншотах интерфейсов плывёт. Поэтому по умолчанию
`INSPOBOT_IMAGE_MODE=document`: исходный файл приходит пиксель в пиксель.
Ценой того, что вместо плитки получается список вложений; `photo` возвращает
прежнее поведение. У инструментов Mobbin запрашивается `image_format="jpg"`:
webp Telegram принимает не везде.

**Ссылка — кнопкой, но не у галереи.** Под каждой находкой стоит URL-кнопка
«Открыть на Mobbin»: она нагляднее ссылки в тексте и не требует живого
процесса — обычная callback-кнопка без него не работала бы, а дайджест между
запусками не живёт.

Исключение — флоу. `sendMediaGroup` не принимает `reply_markup`, кнопку к
галерее прицепить нельзя. Поэтому подпись с кнопкой уходит отдельным
сообщением перед галереей: сначала что это и почему интересно, затем шаги.

**Валидация ответа модели.** Ссылка обязана начинаться с `https://mobbin.com/`;
у экранов дополнительно проверяется, что id — uuid. Для флоу и секций строгой
проверки нет намеренно: их формат id живым ответом не подтверждён, и жёсткое
правило молча выбрасывало бы всё подряд.

**Идемпотентность по дням.** Таблица `runs` помнит успешные запуски. Дёрнуть
задачу ещё раз после сбоя безопасно: пока запуск не завершился успехом, день
считается незакрытым.

## Что где менять

| Хочется | Где |
|---|---|
| другое расписание недели | `python -m inspobot.setup_cli` |
| список получателей | `var/chats.txt`, по id в строке |
| новые темы или оси | `inspobot/catalog.py` |
| формулировки промпта, правила отбора | `inspobot/prompt.py` |
| вид сообщения в Telegram | `inspobot/render.py` |
| время и пояс | cron, launchd или systemd-таймер |
| модель и глубина размышления | `ANTHROPIC_MODEL`, `INSPOBOT_EFFORT` |

## Стоимость

Один запуск — один запрос к Messages API, внутри которого модель делает по
одному обращению к Mobbin на блок и рассматривает несколько десятков картинок.
Картинки дают основную часть входных токенов.

Считать надо по числу **разных подборок**, а не подписчиков: рассылка на сто
чатов стоит столько же, сколько на один. При шести письмах в неделю выходит
около 26 запусков в месяц.

Самый тяжёлый блок — с флоу: `search_flows` приносит превью всех шагов каждого
сценария. Дешевле всего в таком порядке: уменьшить количество флоу в блоке
(`setup_cli`), снизить `INSPOBOT_EFFORT` до `medium`, перейти на
`ANTHROPIC_MODEL=claude-sonnet-5`.
