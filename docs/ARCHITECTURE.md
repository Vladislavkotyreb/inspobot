# Как это устроено

## Путь одной подборки

```
cron / таймер / команда /now
        │
        ▼
  daily.run_once ──── state.Store: сегодня уже слали? ──► выход
        │
        ├─ topics.topics_for(день) ──────────► тема дня: мобильная + десктопная
        ├─ mobbin_auth.get_access_token ─────► access-токен (обновляется сам)
        │
        ▼
  curator.collect
        │  Messages API, beta mcp-client-2025-11-20
        │  mcp_servers = [Mobbin] + tools = [mcp_toolset]
        │  output_config.format = json_schema
        ▼
   Claude сам зовёт search_screens (ios и web), смотрит картинки,
   отбирает лучшее и возвращает JSON по схеме
        │
        ▼
  prompt.parse_digest ─── отсев выдуманного и уже показанного
        │
        ▼
  render.* ──► telegram.Telegram ──► чат
        │
        ▼
  state.Store.mark_seen: эти экраны больше не предлагать
```

Клиентского цикла `tool_use` здесь нет: соединение с MCP-сервером Mobbin держит
сторона Anthropic, поэтому один вызов Messages API покрывает и поиск, и отбор.
Единственное, что обрабатывается вручную, — `stop_reason == "pause_turn"`:
запрос продолжается тем же контекстом.

## Модули

| Файл | Ответственность | Зависит от сети |
|---|---|---|
| `topics.py` | список тем и ротация по дате | нет |
| `catalog.py` | что можно выбрать в мастере: виды, платформы, темы | нет |
| `wizard.py` | машина состояний мастера, кодирование кнопок | нет |
| `models.py` | `Pick`, `Digest` | нет |
| `prompt.py` | системный промпт, JSON-схема, разбор и валидация ответа | нет |
| `render.py` | HTML для Telegram, лимиты длины, экранирование | нет |
| `state.py` | SQLite: что показывали, когда запускались | нет |
| `config.py` | окружение и `.env` | нет |
| `curator.py` | вызов Messages API с MCP-коннектором | да |
| `mobbin_auth.py` | OAuth к Mobbin, обновление токена | да |
| `telegram.py` | Bot API | да |
| `daily.py` | сборка и отправка одной подборки | да |
| `bot.py` | расписание в процессе + команды | да |
| `doctor.py` | самопроверка доступов, подсказка `chat_id` | да |

Первые шесть проверяются тестами целиком, без ключей и без сети. Отсюда и
разделение: `prompt.py` отдельно от `curator.py` именно затем, чтобы разбор
ответа модели можно было проверить, не платя за запрос.

## Почему так

**Дедупликация через `exclude_screen_ids`.** Mobbin — не лента новинок, это
поиск. «Новое» здесь означает «новое для вас», поэтому id показанных экранов
уходят в SQLite, а оттуда — в параметр поиска. Память скользящая: Mobbin
принимает не больше 100 значений, так что через несколько месяцев экран может
вернуться. Это осознанно — иначе список исключений пришлось бы урезать по
какому-то другому, менее понятному правилу.

**Списки тем разной длины.** 14 мобильных и 15 десктопных. Будь они равны,
пара «мобильная тема + десктопная» повторялась бы каждые две недели одним и тем
же набором; при разной длине пара возвращается раз в 210 дней. Это проверяет
`tests/test_topics.py`.

**Валидация ответа модели.** `is_valid_pick` требует, чтобы `screen_id` был
uuid, а `mobbin_url` начинался с `https://mobbin.com/`. Ссылка, которой нет в
ответе инструмента, до Telegram не доедет, даже если модель её сочинит.

**Идемпотентность по дням.** Таблица `runs` помнит успешные запуски. Дёрнуть
задачу ещё раз после сбоя безопасно: пока запуск не завершился успехом, день
считается незакрытым.

## Пошаговый подбор

`/pick` ведёт по четырём шагам и на каждом перерисовывает то же сообщение.
Состояние целиком лежит в `callback_data`: `w|s|i|b|dashboard` — вид,
платформа, аудитория, тема. Отсюда три следствия.

Кнопки не протухают при перезапуске бота: состояние приходит вместе с
нажатием, хранить нечего. Не бывает брошенных наполовину сессий, которые
надо чистить по расписанию. И «назад» — не отдельная ветка в обработчике,
а тот же формат с очищенным последним полем: пришёл неполный выбор — рисуем
шаг, пришёл полный — идём искать.

Ограничение Telegram на `callback_data` — 64 байта, поэтому коды
односимвольные. Что весь каталог в него укладывается, проверяет
`tests/test_wizard.py`: перебирает все достижимые сочетания, а не пример.

Оси выбора соответствуют возможностям Mobbin, а не выдуманы:

| Ось | Чем обеспечена |
|---|---|
| Вид (экран / флоу / секция) | три разных инструмента: `search_screens`, `search_flows`, `search_sections` |
| Платформа | параметр `platform` (`ios`/`web`); у `search_sections` его нет — шаг пропускается |
| Тема | текст запроса |
| **B2B / B2C** | **фильтра нет.** Два разных набора тем со своими формулировками запроса |

Последнюю строку бот проговаривает прямо на шаге выбора аудитории: обещать
фильтрацию, которой нет, — худший вид интерфейсной лжи.

## Что где менять

| Хочется | Файл |
|---|---|
| другие темы утренней рассылки | `inspobot/topics.py` |
| темы и оси в мастере `/pick` | `inspobot/catalog.py` |
| формулировки промпта, правила отбора | `inspobot/prompt.py` |
| вид сообщения в Telegram | `inspobot/render.py` |
| сколько экранов на площадку | `INSPOBOT_PICKS_PER_PLATFORM` в `.env` |
| время и пояс | `INSPOBOT_HOUR`, `INSPOBOT_TZ` (для демона) или cron/таймер |
| модель и глубина размышления | `ANTHROPIC_MODEL`, `INSPOBOT_EFFORT` |

## Стоимость

Один запуск — это один запрос к Messages API, внутри которого модель делает
2–3 обращения к Mobbin и рассматривает несколько десятков картинок. Картинки
дают основную часть входных токенов. Если счёт окажется заметным, дешевле всего
в таком порядке: уменьшить `limit` поиска (`prompt.py`), снизить
`INSPOBOT_EFFORT` до `medium`, перейти на `ANTHROPIC_MODEL=claude-sonnet-5`.
